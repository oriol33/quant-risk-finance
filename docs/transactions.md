# Portfolio transaction schema

Store the workbook at `data/transactions.xlsx`, with one sheet named `transactions`.
Each row represents one executed transaction. Keep current prices, market values,
P&L, and calculated FIFO links out of this input sheet.

## Columns

Use these exact column names. All fields are required except `transfer_id`, which
is required only for transfers. `COLUMN_TYPES` in the Python module defines
these types; `ACTIONS` defines the allowed actions. Dates accept ISO strings
without a timezone; numeric fields are converted to floats and must be finite.
Blank transfer references are represented as missing values.

| Column | Pandas type / allowed values | Description |
|---|---|---|
| `transaction_id` | `string`, unique | Permanent sequential reference, such as `TX000001`. Generated by the writer; store as text. |
| `execution_date` | `datetime64[ns]` | Execution date, displayed as `YYYY-MM-DD`. Include time when needed to order same-day trades; otherwise preserve their execution order in the sheet. |
| `instrument_id` | `string` | Stable identifier for the exact instrument: preferably ISIN, otherwise ticker plus exchange. Use it consistently. |
| `action` | `string`, one of the six actions below | Whether the transaction opens, closes, or transfers units. |
| `quantity` | `float64`, positive | Shares or fund units. Preserve fractional units and original precision. |
| `unit_price` | `float64`, positive | Executed price or NAV per unit, preserving original precision. |
| `currency` | `string`, three uppercase letters | Price and fee currency, such as `EUR`, `USD`, or `GBP`. |
| `fees` | `float64`, nonnegative | Total transaction fees in `currency`; use `0` when none. |
| `transfer_id` | `string`, nullable | Shared reference linking outgoing and incoming transfer transactions. Blank for other actions. |

## Actions

| Value | Meaning |
|---|---|
| `OPEN_LONG` | Buy shares or fund units to own them. |
| `CLOSE_LONG` | Sell or redeem units already owned, matching the oldest eligible lots first. |
| `OPEN_SHORT` | Open an actual short sale of borrowed shares. |
| `CLOSE_SHORT` | Buy back shares to cover a short position. |
| `TRANSFER_OUT` | Units leaving a fund in a qualifying traspaso. |
| `TRANSFER_IN` | Units entering the destination fund in that traspaso. |

Quantities are always positive; the action determines their effect. A closure
must not exceed the available units. Record a deliberate reversal as a closure
and a separate opening.

## Cases covered

- **Partial closure:** TX000007 sells 60 of the 100 units bought in TX000001.
- **Closure across purchases:** TX000008 sells all 10 units from TX000002 and 2 from TX000005;
  TX000010 closes the remaining 3.
- **Short positions:** TX000003 and TX000006 open shorts. TX000009 covers 20 units from TX000003
  and 5 from TX000006 under the proposed FIFO tracking policy; TX000013 covers the last 5.
- **Partial transfer across lots:** TR001 consumes the remaining 40 units from
  TX000001 and 20 from TX000004. The EUR 960 transferred buys 24 FUND_B units.
- **Subsequent partial transfer:** TR002 moves EUR 264 from FUND_B into FUND_C,
  preserving the relevant original acquisition history.
- **Full closure after a transfer:** TX000016 sells the last 30 FUND_A units.

## FIFO and transfer history

The program will generate purchase lots and closure links from these records,
allocating fees proportionally. Keep long and short lots separate; FIFO short
matching is a tracking policy, not a determination of short-sale tax treatment.

For qualifying traspasos, retain both the destination entry date/value and the
original fiscal acquisition dates/costs. A transfer spanning several original
lots must preserve them separately, including through subsequent transfers.
Outgoing and incoming execution dates and unit quantities may differ.

Use transfer actions only for qualifying traspasos. An ordinary redemption
followed by a purchase uses `CLOSE_LONG` and `OPEN_LONG`. See the
[AEAT fund-transfer guidance](https://sede.agenciatributaria.gob.es/Sede/ayuda/manuales-videos-folletos/manuales-ayuda-presentacion/irpf-2025/7-cumplimentacion-irpf/7_6-ganancias-perdidas-patrimoniales/7_6_3-reglas-especiales-calculo/7_6_3_3-acciones-participaciones-instituciones-inversion-colectiva.html).

This initial schema assumes complete acquisition history. Historical transfers
without their original transactions require additional opening-lot information
from the broker before fiscal FIFO can be reconstructed.

## Manage transactions from Python

The functions in `src/data_io/transactions.py` use `data/transactions.xlsx` by
default; pass `path=...` to use another workbook with the same columns and
single `transactions` sheet. Each function reads a DataFrame, modifies it,
and rewrites the sheet with `to_excel(index=False)`. No named Excel Table or
custom formatting is preserved. Each function returns a list of affected IDs.

```python
from src.data_io.transactions import (
    add_transactions,
    edit_transactions,
    delete_transactions,
)

transaction = {
    "execution_date": "2026-09-10",
    "instrument_id": "IE00B03HD191",
    "action": "OPEN_LONG",
    "quantity": 12.65,
    "unit_price": 63.1993,
    "currency": "EUR",
    "fees": 0,
}
ids = add_transactions(transaction)  # Or a list of transaction dictionaries.
edit_transactions(ids[0], {"quantity": 15, "fees": 1})  # Only changed fields.
delete_transactions(ids[0])  # Or a list of IDs; removes rows permanently.
```

- Pass decoded JSON dictionaries (`json.loads` / `json.load`). Omit
  `transaction_id`: additions generate it from the highest number currently in
  the workbook. Edits preserve it; deletions do not renumber surviving rows.
- Deleting the highest ID allows its number to be reused. An empty workbook
  starts again at `TX000001`.
- Unknown fields and invalid values are rejected; missing edit/delete IDs raise
  `KeyError`. Types and values are checked when reading and before saving.
  A temporary file replaces the workbook only after a successful write.
- These functions manage records only; FIFO, holdings, and transfer matching
  are calculated separately. Keep Excel closed and use one writer at a time.
